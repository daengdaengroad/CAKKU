## 내일 데스크탑에서 시작하는 법

```bash

git pull

npm run shorts:samples
npm run shorts -- --input tools/shorts/input.example.json
open tools/shorts/out/*.mp4
```

구글 클라우드 콘솔 > Cloud Text-to-Speech API 사용 설정 > API 키 발급 > `tools/shorts/.env` 에
`GOOGLE_TTS_API_KEY=` 로 넣는다. 대본 품질까지 보려면 `GEMINI_API_KEY` 도 같이.

npm run shorts -- --script out/매장명.script.json

## 지금까지 된 것

CLI 파이프라인 전체 (사진 + 매장명 + 메뉴 → 9:16 MP4). 자세한 건 `README.md`.

- 대본 생성 (Gemini/Claude, 키 없으면 템플릿 폴백)
- 문장별 TTS mp3 (구글 Cloud TTS, 키 없으면 같은 길이 무음 mp3)
- mp3 길이를 ffprobe로 실측해 사진 노출 시간 + 자막 타이밍에 사용
- 켄번스 4종 순환 + ASS 자막 + 오프닝 타이틀 + 마무리 카드 + 선택적 배경음악
- `--draft` / `--script` 2단계 편집, 문장별 `say` / `caption` / `photo` 지정
- 문장 내용 기준 TTS 캐시 (한 문장만 고치면 나머지 재사용)

**렌더링 실측**: 4코어 2.1GHz에서 21.5초 영상에 약 10초. 영상 길이의 절반.

## 미해결 — 다음에 바로 손볼 것

### 1. 가로 사진이 9:16 센터 크롭에서 망가진다 (우선순위 높음)

실제 버거 사진으로 테스트하다 확인. 클로즈업 사진은 괜찮은데, 트레이 부감샷처럼
좌우로 넓은 구도는 양쪽이 잘려 "감자튀김 반쪽 + 버거 반쪽"이 된다.
소상공인이 주는 사진은 대부분 가로라 절반이 이렇게 나온다.

고치는 법: 크롭하지 말고 사진 전체를 폭에 맞춰 넣은 뒤, 위아래 빈 공간을 같은 사진의
흐린 확대본으로 채운다 (릴스 자동 변환 방식). `lib/render.js` 의 세그먼트 필터 수정.
예상 30분.

### 2. 목소리를 아직 못 들어봤다

TTS 키가 없어서 전부 무음으로만 확인했다. "3만원짜리로 보이는지"는 소리까지 들어야
판단 가능. 키 하나면 끝난다.

### 3. 편당 원가 실측

키 넣고 한 편 뽑으면 `report.json` 의 `timings` 에 TTS/대본 생성 시간이 찍힌다.
구독료 산정에 필요한 숫자.

## 논의한 것 (아직 결정 아님)

**사업 모델이 건당 3만원 → 월 구독제로 바뀜. 이용자 = 업소 사장님 본인.**

이게 맞다면 따라오는 것들:

- 사장님이 사진 업로드 → 대본 수정 → 영상 수령까지 혼자 끝내야 함.
  지금 CLI는 제품이 아니라 **엔진**이고, 서버가 이걸 호출하는 구조가 된다.
- 편당 변동비는 50원 안쪽으로 추정 (TTS 3원 + 렌더링 CPU + 전송).
  → 편수 티어를 나눌 원가 근거가 없다. 단일 요금제 + 편수 무제한 권장.
- 진짜 위험은 원가가 아니라 **이탈**. 소상공인 구독은 3개월째 "안 써서" 해지한다.
  → 사장님이 아무것도 안 해도 주 1회 자동 생성되어 있는 구조가 핵심.
    기존 사진 재활용 + 요일/계절 멘트만 교체. TTS 캐시와 대본 파일 구조가 여기 그대로 쓰인다.
- 가격 정하기 전에 확인할 숫자는 **3개월 유지율** 하나. 검증 5곳에 3개월 주고
  "이제 월 29,000원인데 계속 쓰시겠어요?"를 물어보는 게 가격 실험보다 먼저.
- CAC가 10만원을 넘으면 월 29,000원은 회수 기간이 너무 길어진다. 그 숫자가 나오면 재계산 필요.

### 사장님 편집 화면 설계 (만들 때)

전체 텍스트 입력창 하나를 주면 대본이 산으로 간다. 문장 카드로 쪼갠다.

- 문장마다 카드 한 장, 입력창 하나, **최대 30자 제한** (제한이 대본 구조를 지켜준다)
- 카드에 사진 썸네일, 탭하면 교체
- 카드마다 미리듣기 버튼 (그 문장만 TTS) — 오타는 귀로 들어야 잡힌다
- 문장 추가/삭제는 막거나 5~7개로 제한

## 순서 (권장)

1. 영상 품질 확인 (TTS 키 1개) ← **여기서 접을지 말지가 갈린다**
2. 가로 사진 크롭 수정
3. 서버 API 2개 (`server/`에 대본 뽑기 / 렌더링). express·multer 이미 있음.
   단 Railway에 ffmpeg 설치 필요하고, 렌더링이 API 응답을 잡아먹으니 큐가 필요하다.
4. 앱 편집 화면

2번부터 하고 싶어지겠지만 1번을 먼저. 영상이 별로면 3·4번은 버리는 코드가 된다.
