# 매장 홍보 쇼츠 자동 생성기 (검증용)

사진 5장 + 매장명 + 메뉴 2개를 넣으면 9:16 세로 MP4가 나온다.
UI 없이 CLI만 있는 검증 단계 도구다. 목적은 하나 — **결과물이 3만원짜리로 보이는지** 확인하는 것.

```
사진 5장 + 매장명 + 메뉴 2개
      ↓  대본 생성 (Gemini / Claude, 문장 수 = 사진 수)
      ↓  문장별 TTS mp3 (구글 Cloud TTS)
      ↓  mp3 길이 측정 (ffprobe)  ← 이 값이 사진 노출 시간이자 자막 타이밍
      ↓  켄번스(확대/축소/패닝) + 자막 + 마무리 카드 합성 (ffmpeg 한 방)
   1080x1920 MP4 + 단계별 소요 시간 리포트
```

## 설치

```bash
# macOS
brew install ffmpeg
brew tap homebrew/cask-fonts && brew install --cask font-nanum-gothic

# Ubuntu / Debian
sudo apt-get install -y ffmpeg fonts-nanum
```

Node는 18 이상이면 된다. npm 패키지는 추가로 설치할 게 없다 (ffmpeg + 내장 fetch만 쓴다).

키는 `tools/shorts/.env` 에 넣는다 (`.env.example` 복사). `server/.env` 도 자동으로 읽으므로
이미 `GEMINI_API_KEY` 가 거기 있으면 그대로 쓰인다.

```bash
cp tools/shorts/.env.example tools/shorts/.env
```

## 돌려보기

```bash
# 1) 샘플 사진 5장 만들고 파이프라인 전체 확인 (API 키 없어도 돌아간다)
npm run shorts:samples
npm run shorts -- --input tools/shorts/input.example.json

# 2) 진짜 매장 사진으로
npm run shorts -- --store "화정동 손칼국수" \
                  --menus "바지락 손칼국수,들깨 수제비" \
                  --photos ./photos            # 폴더를 주면 파일명 순으로 읽는다
```

키가 없으면 대본은 템플릿으로, 음성은 **무음 mp3**로 대체된다. 타이밍/렌더링 구조는
그대로 검증되지만 소리는 없다. `GOOGLE_TTS_API_KEY` 를 넣는 순간 같은 명령이 실제 목소리로 나온다.

## 옵션

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--input <file>` | - | 입력 JSON (`input.example.json` 참고) |
| `--store`, `--menus`, `--photos`, `--note` | - | JSON 대신 직접 지정 (JSON보다 우선) |
| `--music <file>` | 없음 | 배경음악 (음성 대비 12% 볼륨으로 믹스) |
| `--tts auto\|google\|offline` | `auto` | `auto`는 키가 있으면 구글, 없으면 무음 |
| `--preset` | `veryfast` | x264 프리셋. 화질/속도 트레이드오프 |
| `--crf` | `20` | 낮을수록 고화질·큰 용량 |
| `--lines` | 사진 수 | 문장(컷) 수. 사진보다 크게 주면 같은 사진을 다른 움직임으로 재사용한다 |
| `--gap` | `0.25` | 문장 사이 쉬는 시간(초) |
| `--tail` | `1.0` | 마지막 컷 여운(초). 이 구간에 마무리 카드가 뜬다 |
| `--out <dir>` | `tools/shorts/out` | 출력 폴더 |
| `--keep` | - | 중간 파일(문장별 mp3, ASS 자막) 보존 |

## 결과

```
out/
  화정동-손칼국수-1789302726005.mp4          # 1080x1920, H.264 + AAC
  화정동-손칼국수-1789302726005.report.json  # 문장별 길이/타이밍 + 단계별 소요 시간
```

## 렌더링 시간 (측정값)

4코어 2.1GHz Xeon, 사진 5장(4032x3024 고노이즈 JPEG = 최악 조건), 21.5초 영상 기준:

| preset | 렌더링 | 영상 1초당 | 용량 |
|---|---|---|---|
| ultrafast | 8.8초 | 0.41초 | 78MB |
| **veryfast (기본)** | **10.3초** | **0.48초** | **11MB** |
| medium | 23.0초 | 1.07초 | 16MB |

즉 **영상 길이의 절반 정도 시간**이면 렌더가 끝난다. 25초 쇼츠 한 편에 10~12초.
사진이 흔한 폰 사진(2~4MB)이면 이보다 빠르다.

여기에 대본 생성(LLM 1회)과 TTS 왕복(문장당 1회)이 더 붙는데, **이 두 개는 아직 실측 못 했다**
(API 키 없이 측정한 수치라 대본은 템플릿, TTS는 무음으로 돌렸다). 키를 넣고 한 번 돌리면
`report.json` 의 `timings` 에 그대로 찍힌다. 어느 쪽이든 네트워크 대기라 CPU는 놀고 있으므로,
**렌더링은 이 사업의 병목이 아니다.** 병목은 사진 수급이다.

## 설계 메모

- **문장 수 = 사진 수.** 사진 한 장이 문장 하나를 읽는 동안 화면에 머문다. TTS mp3 길이를
  실제로 재서(`ffprobe`) 쓰기 때문에 자막·사진·음성이 어긋날 구조적 여지가 없다.
- **켄번스는 4가지 움직임을 순환**한다 (확대 / 축소 / 좌→우 / 아래→위). zoompan은 입력 해상도
  기준 정수 픽셀로 움직여서 떨림이 생기므로, 합성 전에 사진을 2배로 키워둔다.
- **자막 아래 그라데이션(scrim)** 을 깔아 밝은 음식 사진 위에서도 글씨가 읽히게 했다.
  `overlay=format=yuv420` 로 붙여야 RGB 변환이 안 일어나 렌더가 느려지지 않는다 (12.6초 → 8.3초).
- **컷 전환은 하드컷.** 크로스페이드를 넣으면 겹치는 시간만큼 전체 길이가 줄어 자막 타이밍이
  밀린다. 문장 시작에 딱 맞춰 끊는 편이 숏폼 문법에도 맞다.
- **없는 사실을 쓰지 않게** 대본 프롬프트에서 수상 이력·가격·영업시간·원산지를 금지했다.
  소상공인 홍보물은 여기서 사고가 난다.
