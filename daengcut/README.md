# 댕컷 (DaengCut)

**반려견 영상만 넣으면 유튜브 숏츠가 나오는 자동 편집기.**

찍어둔 영상을 올리면 볼 만한 구간을 골라 컷을 잡고, 장면을 보고 대본을 쓰고,
자막과 내레이션을 얹어 세로 영상으로 뽑아 유튜브에 올립니다.
마음에 안 드는 부분은 브라우저에서 직접 고칠 수 있습니다.

```
촬영한 영상 → 분석 → 컷 → 대본 → 자막·내레이션 → [편집] → 렌더 → 유튜브
```

---

## 시작하기

### 터미널을 안 써봤다면 (윈도우 기준)

1. **Node.js 설치** — [nodejs.org](https://nodejs.org/ko/download) 에서 초록색 **LTS** 버튼을
   눌러 받고, 실행해서 "다음"만 계속 누르면 됩니다. 한 번만 하면 됩니다.
2. **코드 받기** — 깃허브 저장소에서 **Code → Download ZIP** 으로 받아 압축을 풉니다.
3. **실행** — 압축 푼 폴더 안의 `daengcut` 폴더로 들어가서
   **`댕컷 시작.bat`** 을 더블클릭합니다. (맥이라면 `댕컷 시작.command`)

검은 창이 뜨면서 알아서 설치하고, 끝나면 브라우저가 자동으로 열립니다.
**처음 한 번만 2~5분 걸리고, 그 다음부터는 10초면 켜집니다.**
끌 때는 검은 창을 닫으면 됩니다.

> 윈도우가 "PC를 보호했습니다" 라고 막으면 **추가 정보 → 실행** 을 누르세요.
> 인터넷에서 받은 파일이라 뜨는 경고입니다.

### 터미널을 쓸 줄 안다면

```bash
npm install
npm run setup     # .env 생성 + 한글 자막 폰트 다운로드
npm run dev       # http://localhost:5173
```

`ffmpeg` 은 `npm install` 할 때 같이 들어오므로 따로 설치하지 않아도 됩니다.

### 한 프로세스로 돌리기 (배포용)

```bash
npm run build
npm start          # http://localhost:4000 에서 API 와 편집 화면을 같이 서빙
```

## 설정 (.env)

`npm run setup` 이 만들어준 `.env` 를 열어 필요한 것만 채우면 됩니다.
**아무것도 안 채워도 서버는 뜹니다.** 채우지 않은 기능만 꺼진 채로 동작합니다.

| 채우면 켜지는 것 | 항목 |
| --- | --- |
| 대본·자막 자동 작성 | `ANTHROPIC_API_KEY` |
| 내레이션 목소리 | `TTS_PROVIDER` + 해당 제공자 키 |
| 유튜브 자동 업로드 | `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET` |

### 1. 대본 (필수는 아니지만 이게 핵심)

[console.anthropic.com](https://console.anthropic.com) 에서 API 키를 만들어 넣습니다.

```env
ANTHROPIC_API_KEY=sk-ant-...
ANTHROPIC_MODEL=claude-opus-5
```

키가 없으면 **컷은 자동으로 잡히지만 자막은 직접 써야 합니다.**

### 2. 내레이션 목소리

셋 중 하나를 고릅니다. 안 켜도 자막만으로 숏츠는 충분히 굴러갑니다.

```env
# 구글 (유튜브 업로드와 같은 GCP 프로젝트를 써도 됩니다)
TTS_PROVIDER=google
GOOGLE_APPLICATION_CREDENTIALS=/경로/서비스계정.json
GOOGLE_TTS_VOICE=ko-KR-Chirp3-HD-Leda

# 또는 일레븐랩스 (한국어 감정 표현이 가장 자연스러움)
TTS_PROVIDER=elevenlabs
ELEVENLABS_API_KEY=...
ELEVENLABS_VOICE_ID=...

# 또는 OpenAI
TTS_PROVIDER=openai
OPENAI_API_KEY=...
```

구글을 쓸 경우 GCP 콘솔에서 **Cloud Text-to-Speech API** 를 사용 설정하고,
서비스 계정을 만들어 JSON 키를 받아 그 경로를 적습니다.

### 3. 유튜브 자동 업로드

1. [Google Cloud Console](https://console.cloud.google.com) 에서 프로젝트를 만듭니다.
2. **YouTube Data API v3** 를 사용 설정합니다.
3. **OAuth 동의 화면** 을 구성합니다 (외부 → 테스트 사용자에 본인 계정 추가).
4. **사용자 인증 정보 → OAuth 클라이언트 ID → 웹 애플리케이션** 을 만듭니다.
5. 승인된 리디렉션 URI 에 `http://localhost:4000/api/youtube/callback` 을 넣습니다.
6. 받은 클라이언트 ID/보안 비밀을 `.env` 에 적습니다.

편집 화면에서 **유튜브에 올리기 → 계정 연결하기** 를 한 번 누르면 이후로는 계속 쓸 수 있습니다.

> **하루 업로드 횟수 제한**: 유튜브 API 기본 할당량은 하루 10,000 유닛이고
> 영상 업로드 한 번에 1,600 유닛이 듭니다. 하루 6편 정도가 한계입니다.
> 하루 한 편 올리는 용도라면 넉넉하지만, 나중에 여러 사람이 쓰는 서비스로 낼 거라면
> 구글에 할당량 증설을 신청해야 합니다.

## 쓰는 순서

1. **영상 올리기** — 첫 화면에 끌어다 놓습니다. 여러 개를 한 번에 올리면 이어붙여 한 편으로 만듭니다.
2. **자동으로 돌아감** — 분석 → 컷 → 대본 → 내레이션 → 렌더까지 알아서 진행됩니다.
3. **고치기** — 편집 화면에서:
   - **자막**: 문구 수정, 강조 지정, 추가·삭제. 타임라인에서 끌어 위치 조정
   - **컷**: 앞뒤 자르기, 순서 바꾸기, 나누기, 배속, 화면 채우기 방식, 확대·위치
   - **소리**: 내레이션 문장 수정 후 목소리 다시 만들기, 배경음악 넣기
   - **스타일**: 자막 폰트·크기·색·테두리·위치
   - **유튜브**: 제목·설명·태그
4. **영상 만들기** → **유튜브에 올리기**

미리보기는 렌더링 없이 즉시 반영됩니다. 자막을 고치면 바로 화면에서 확인할 수 있고,
최종 렌더는 다 고친 다음 한 번만 돌리면 됩니다.

## 어떻게 동작하나

### 볼 만한 구간 고르기

영상을 세 가지로 훑습니다.

- **장면 전환** — 화면이 확 바뀌는 지점 (컷의 자연스러운 경계)
- **움직임** — 프레임 간 변화량 (뛰는 구간은 높고, 자는 구간은 낮음)
- **소리 크기** — 짖거나 사람이 말하는 구간

셋을 합쳐 "볼 만한 정도" 곡선을 만들고, 그 위에서 창을 밀어가며 좋은 구간을 고릅니다.
목표 길이를 못 채워도 **점수가 낮은 구간은 넣지 않습니다.** 길이를 채우려고
지루한 장면을 끼워 넣는 것보다 짧고 밀도 높은 편이 낫기 때문입니다.

### 대본 쓰기

클립마다 대표 프레임 2장을 뽑아 Claude 에게 보여주고, 자막·내레이션·제목·태그를
한 번에 받습니다. 화면에 실제로 보이는 것만 쓰도록 하고, 강조 자막은 영상당 하나만 남깁니다.

### 타임라인이 중심입니다

AI가 처음 한 벌 만들어주는 것도, 브라우저에서 고치는 것도, 렌더러가 읽는 것도
전부 **하나의 타임라인 JSON** 입니다. 같은 타임라인이면 언제 돌려도 같은 영상이 나옵니다.

```jsonc
{
  "clips":     [{ "sourceId": "...", "in": 3.0, "out": 8.0, "speed": 1, "framing": { "mode": "cover" } }],
  "captions":  [{ "start": 0.2, "end": 2.4, "text": "오늘도 산책 나온 우리 강아지", "emphasis": true }],
  "narration": [{ "start": 0.2, "text": "...", "audioFile": "audio/n_a1b2.mp3", "durationSec": 2.4 }],
  "music":     { "file": "audio/bgm.mp3", "gain": 0.18, "fadeInSec": 0.6, "fadeOutSec": 1.2 },
  "meta":      { "title": "...", "description": "...", "tags": ["강아지", "쇼츠"] }
}
```

### 렌더링

한 번의 ffmpeg 실행으로 클립 이어붙이기, 9:16 프레이밍, 배속, 자막 굽기,
원본·배경음·내레이션 믹싱과 내레이션 구간 더킹까지 처리합니다.

- 세로 영상은 잘라서 꽉 채우고(`cover`), 가로 영상은 뒤에 흐린 배경을 깔아(`blur`)
  강아지가 화면 밖으로 잘리지 않게 합니다.
- 자막 줄바꿈은 글자 수가 아니라 **실제 글자 폭**으로 계산합니다.
  한글은 한 글자가 알파벳 두 배 폭이라, 글자 수로 세면 화면 밖으로 삐져나갑니다.
- 편집 화면의 미리보기도 **같은 줄바꿈 규칙과 같은 폰트 파일**을 씁니다.
  미리보기에서 두 줄이면 결과물도 두 줄입니다.

## 비용

한 편 만들 때 드는 돈은 대본 생성이 거의 전부입니다.

| 모델 | 한 편당 대략 |
| --- | --- |
| `claude-opus-5` (기본) | 약 $0.10 |
| `claude-sonnet-5` | 약 $0.06 |

이미지 10장 안팎 + 짧은 출력 기준입니다. 매일 한 편이면 한 달에 몇 천 원 수준입니다.
아껴야 한다면 `.env` 의 `ANTHROPIC_MODEL` 을 `claude-sonnet-5` 로 바꾸세요.

TTS 와 유튜브 업로드는 제공자마다 무료 한도가 달라 각 콘솔에서 확인하는 게 정확합니다.
**렌더링은 내 컴퓨터에서 도니까 공짜입니다.**

## 폴더 구조

| 폴더 | 역할 |
| --- | --- |
| `server/src/media` | ffmpeg 래퍼, 영상 분석(장면 전환·움직임·소리), 프레임 추출, 미리보기 생성 |
| `server/src/timeline` | 편집 문서(타임라인)의 타입·검증·자동 구성 |
| `server/src/render` | 자막(ASS) 생성, 프레이밍 계산, 폰트 탐색, 최종 렌더 |
| `server/src/ai` | 비전 분석 → 대본 생성, TTS |
| `server/src/jobs` | 진행률을 보고하며 도는 작업 큐와 파이프라인 |
| `server/src/youtube` | OAuth 연결과 업로드 |
| `web/src` | 편집 화면 (미리보기, 타임라인, 패널) |
| `workspace/` | 원본·중간 산출물·결과물. 통째로 지워도 프로그램은 멀쩡합니다 |

## 자막 폰트 바꾸기

`assets/fonts/` 에 `.ttf` / `.otf` 를 넣으면 자동으로 인식합니다.
폰트 파일의 글자 표를 직접 읽어 **한글 글리프가 실제로 들어있는 폰트만** 자막에 씁니다.
한글 없는 폰트를 골라 자막이 네모로 깨지는 일은 없습니다.

`npm run setup` 은 프리텐다드, 검은고딕, 고딕 A1 세 가지를 받아둡니다.

## 나중에 서비스로 낼 때

지금은 내 컴퓨터에서 도는 프로그램이지만, 서버에 그대로 올려도 동작하게 만들어 두었습니다.
`npm run build && npm start` 하나면 API 와 편집 화면이 같이 뜹니다.

그때 손봐야 할 것들:

- **사용자 구분** — 지금은 로그인이 없습니다. 프로젝트가 `workspace/projects/<id>` 로 나뉘어 있으니
  여기에 소유자만 붙이면 됩니다.
- **저장소** — 프로젝트 상태가 JSON 파일입니다. 사람이 늘면 데이터베이스로 옮겨야 합니다.
  읽고 쓰는 곳이 `server/src/store/projects.ts` 한 군데뿐이라 갈아끼우기 쉽습니다.
- **렌더링 서버** — 영상 인코딩이 CPU 를 다 씁니다. 사용자가 늘면 렌더링만 따로 떼어
  작업 큐(Redis 등)로 돌려야 합니다. 지금은 프로젝트당 하나씩만 돌게 막아두었습니다.
- **유튜브 할당량** — 위에 적은 하루 6편 제한을 구글에 신청해서 늘려야 합니다.
